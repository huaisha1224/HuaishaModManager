# Mod 自动更新任务单

目标：支持 Nexus 来源 Mod 的更新检查、手动确认更新和批量更新。本地手动导入、没有 Nexus 来源信息的 Mod 暂不做自动更新。

## 1. 保存 Nexus 来源信息

- [x] 为本地 Mod 数据增加 `updateSource` 字段。
- [x] 从 Nexus 下载完成并导入本地 Mod 时，自动保存游戏域名、Mod ID、文件 ID、文件名、版本、页面地址和封面。
- [x] 数据迁移时兼容旧 Mod，旧数据没有来源信息也能正常使用。
- [x] 整合包导出 / 导入时保留 `updateSource`。

## 2. 检查更新

- [x] 增加单个 Mod 检查更新方法。
- [x] 增加当前游戏全部 Nexus 来源 Mod 的检查更新方法。
- [x] 通过 Nexus 详情接口获取文件列表，优先匹配当前文件 ID、同分类文件和主文件。
- [x] 不只比较版本号，也比较文件 ID 和上传时间。
- [x] 在 Mod 行显示“有更新 / 已是最新 / 无法检查”状态。

## 3. 手动确认更新

- [x] 有更新时提供“更新”按钮。
- [x] 下载前展示目标文件名、当前版本、最新版本。
- [x] 无法直接下载时不报错，打开 Nexus 页面等待浏览器回传 NXM。
- [x] 下载任务保留原 Mod 的更新上下文，下载完成后能替换对应 Mod。

## 4. 安全替换

- [x] 更新前备份旧 Mod 缓存目录。
- [x] 如果旧 Mod 已启用，先卸载旧部署。
- [x] 导入新文件后保留原 Mod 的标签、排序、类型、备注、封面和来源信息。
- [x] 更新失败时保留旧 Mod，不破坏现有可用状态。
- [x] 更新成功后，如果原 Mod 已启用，按当前游戏规则重新安装。

## 5. 批量更新

- [x] 增加“检查当前游戏更新”。
- [x] 增加“更新全部可更新 Mod”。
- [x] 批量更新逐个执行，单个失败不影响后续。
- [x] 显示批量更新进度和失败原因。

## 6. 自动检查

- [ ] Mod 更新自动检查（当前暂缓，应用启动检查只用于软件自身更新）。
- [ ] Mod 更新检查间隔和任务快照。
- [ ] 自动检查只提示，不自动替换文件。

## 暂缓

- [ ] 非 Nexus 来源 Mod 的更新识别。
- [ ] 前置依赖自动判断。
- [ ] 完全无人值守自动更新。
